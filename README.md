# 夜语 · 情绪共鸣社交小程序 README

## 🧭 项目概述
**项目名称**：夜语（YeYu）  
**目标**：在微信小程序中构建一个安全、匿名、即时的情绪共鸣空间，让用户能在 3 秒内表达情绪，并获得回应。  
**应用场景**：孤独/焦虑时刻，帮助用户快速获得理解与陪伴。  
**黑客松定位**：MVP 原型，重点展示“情绪表达 → 共鸣 → 安全反馈”核心闭环。

---

## 🎯 产品目标
1. 用户能**快速标注情绪**并发布内容（≤3步）。
2. 系统能基于情绪相似度推荐共鸣动态。
3. 整体体验匿名，轻量、安全、无社交压力。

---

## ✅ 功能需求（MVP）
| 模块 | 功能描述 | 验收标准 |
|------|-----------|-----------|
| 🎭 情绪表达 | 用户通过滑盘选择"价度×唤醒度"并输入文字 | 发布流程≤3步，UI响应<200ms |
| 🚀 发布系统 | 匿名发布动态到共鸣流 | 成功率100%，匿名信息不可逆向 |
| 💬 共鸣流 | 展示相似情绪的帖子 | 相似度算法返回结果<2s |
| 💗 共鸣互动 | 共鸣按钮 + 评论 | 互动响应<200ms |
| 🔄 数据同步 | 页面进入自动同步 + 下拉刷新同步 | 每次进入页面自动获取最新数据，下拉刷新可手动同步 | 

---

## 🖥️ 前端技术栈
- **框架**：微信小程序原生框架（WXML + WXSS + JS）
- **状态管理**：轻量全局 store（app.js 全局 data 或 Zustand-like 实现）
- **UI组件**：自定义情绪滑盘 + 微信基础组件
- **路由结构**：
  - `/pages/index`：主页（Home）- 用户发布情绪帖子
  - `/pages/feed`：共鸣流 - 查看帖子、共鸣（点赞）、评论  

---

## ⚙️ 数据方案
- **开发阶段**：使用模拟数据（Mock Data）
- **数据格式**：JSON格式，存储在本地文件或前端代码中
- **数据结构**：包含用户帖子内容、用户ID、用户名、发帖时间、情绪、情绪指数

## 📦 模拟数据结构

### 帖子数据结构
```javascript
{
  postId: String,           // 帖子ID（唯一标识）
  userId: String,           // 用户ID（匿名）
  username: String,         // 用户名（匿名，如"用户1234"）
  content: String,          // 帖子内容（≤300字）
  emotion: String,          // 情绪标签（如"开心"、"焦虑"、"平静"等）
  emotionValue: Number,     // 情绪指数（价度，0-10）
  arousalValue: Number,     // 唤醒度（0-10）
  timestamp: Number,        // 发帖时间（时间戳）
  likeCount: Number,        // 共鸣数（点赞数）
  commentCount: Number,     // 评论数
  comments: Array           // 评论列表
}
```

### 评论数据结构
```javascript
{
  commentId: String,        // 评论ID
  userId: String,           // 评论者ID（匿名）
  username: String,         // 评论者名称（匿名）
  content: String,          // 评论内容（≤300字）
  timestamp: Number         // 评论时间（时间戳）
}
```

## 📌 注意事项

**用户隐私**：所有内容匿名存储，不保留实名或手机号。

**开发重点**：
- 专注于前后端核心功能开发
- **使用模拟数据进行开发测试**，不涉及真实数据库
- 主要完成两个界面：主页（发布）和共鸣流（浏览、点赞、评论）
- 模拟数据包含：用户帖子内容、用户ID、用户名、发帖时间、情绪、情绪指数

**开发流程**：
- 使用GitHub进行版本控制
- 先创建模拟数据文件（至少100条测试数据）
- 实现Mock API函数（获取列表、发布、点赞、评论）
- 实现前端UI和基础交互
- 前端调用Mock API进行联调
- 最后进行功能测试和优化

**数据同步机制**：
- 共鸣流界面每次进入（`onShow`）时自动同步最新数据
- 支持下拉刷新手动同步数据
- 上拉加载更多实现分页加载（每次20条）
- 点赞和评论操作后，仅更新本地数据，无需重新请求整个列表
