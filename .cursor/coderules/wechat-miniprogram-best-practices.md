## 代码结构与组织

### 1.1 目录结构规范
- 必须遵循微信小程序标准目录结构
- 页面文件统一使用 `index.js`, `index.wxml`, `index.wxss`, `index.json` 命名
- 组件必须放在 `components/` 目录下
- 工具函数统一放在 `utils/` 目录
- 云函数调用封装统一放在 `services/` 目录
- 常量定义统一放在 `constants/` 目录
- 图片资源统一放在 `images/` 目录

### 1.2 命名规范
- **目录命名**：使用小写字母，多个单词用连字符连接（kebab-case）
- **文件命名**：工具文件使用描述性名称，遵循驼峰命名法
- **变量/函数命名**：使用驼峰命名法（camelCase）
- **常量命名**：使用大写字母和下划线（UPPER_SNAKE_CASE）
- **类名命名**：使用帕斯卡命名法（PascalCase）

### 1.3 代码组织原则
- 每个页面/组件必须保持单一职责
- 可复用的逻辑必须抽取到独立文件
- 避免代码重复，抽取公共函数
- 按功能模块组织代码，保持结构清晰

## 代码质量规范

### 2.1 Clean Code 原则
- **函数职责单一**：每个函数只做一件事，函数长度不超过50行
- **变量命名清晰**：使用有意义的变量名，避免单字母变量（循环变量除外）
- **避免魔法数字/字符串**：所有常量必须定义在 `constants/` 目录
- **移除无用代码**：删除未使用的导入、变量和函数
- **代码注释**：复杂逻辑必须添加注释说明，函数必须有 JSDoc 注释

### 2.2 代码格式规范
- 必须配置 ESLint 并遵循规范
- 使用统一的代码格式化工具（如 Prettier）
- 代码提交前必须通过 ESLint 检查
- 缩进使用 2 个空格，不使用 Tab

### 2.3 代码复用规范
- 可复用的 UI 组件必须封装为独立组件
- 可复用的业务逻辑必须抽取为工具函数
- 避免在多个文件中重复相同的代码逻辑

## 性能优化规范

### 3.1 页面加载优化
- 非首屏页面必须使用分包加载
- 必须启用 `lazyCodeLoading` 按需加载组件
- 图片必须使用合适的 `mode` 属性，启用 `lazy-load`
- 大图片必须使用云存储或 CDN，避免打包到小程序中

### 3.2 渲染性能优化
- 长列表必须使用虚拟列表组件
- 必须避免频繁调用 `setData`，合并多次更新为一次
- `setData` 只更新需要渲染的数据，避免传输不必要的数据
- 列表渲染必须使用 `wx:key` 指定唯一标识

### 3.3 事件处理优化
- 高频事件（输入、滚动、滑动）必须使用防抖或节流
- 列表项点击使用事件委托，通过 `data-` 传递参数
- 避免在事件处理函数中进行复杂计算

## 微信云开发规范

### 4.1 云函数开发规范
- 所有云函数必须有完整的错误处理和错误返回
- 云函数入口必须验证所有输入参数
- 云函数返回数据必须包含 `success` 字段标识成功/失败
- 云函数中必须使用 try-catch 捕获异常

### 4.2 数据库操作规范
- 为常用查询字段创建数据库索引
- 批量操作使用批量写入，减少请求次数
- 查询数据时使用 `field()` 只返回必要字段
- 复杂统计查询优先使用聚合查询而非客户端计算

### 4.3 云存储规范
- 文件上传前必须检查文件大小和类型
- 图片上传必须使用压缩选项
- 上传失败必须有错误处理和用户提示

## 安全与隐私保护规范

### 5.1 内容安全规范
- **强制要求**：所有用户输入内容必须经过 `msgSecCheck` 安全检测
- 安全检测失败时必须拒绝操作，不允许绕过
- 敏感内容必须立即屏蔽，不允许展示

### 5.2 用户隐私保护规范
- 不存储用户真实身份信息（openid、userInfo、phoneNumber、realName）
- 必须使用匿名化处理用户数据
- 敏感信息展示前必须脱敏处理
- 数据访问必须遵循最小权限原则

### 5.3 权限控制规范
- 数据库权限必须在云控制台正确配置
- 禁止客户端直接写入敏感数据，必须通过云函数
- 云函数必须验证调用者权限

## UI/UX 规范

### 6.1 响应式设计规范
- 必须使用 `rpx` 单位适配不同屏幕尺寸
- 必须适配安全区域（iPhone X 等设备的刘海屏）
- 布局必须考虑不同屏幕宽高比

### 6.2 交互反馈规范
- 所有异步操作必须显示加载状态（`wx.showLoading`）
- 操作完成后必须隐藏加载状态（`wx.hideLoading`）
- 错误提示必须友好清晰，提示用户如何处理
- 网络错误、权限错误等常见错误必须有对应的用户提示

### 6.3 动画性能规范
- 动画必须使用 `transform` 和 `opacity` 属性（触发 GPU 加速）
- 避免动画 `margin`、`width`、`height` 等触发重排的属性
- 动画时长必须合理，避免过长影响性能

## 错误处理规范

### 7.1 全局错误处理
- 必须在 `app.js` 中设置全局错误监听（`wx.onError`）
- 必须处理未捕获的 Promise 拒绝（`wx.onUnhandledRejection`）
- 错误必须上报到监控平台或日志系统

### 7.2 网络请求规范
- 所有网络请求和云函数调用必须统一封装
- 封装层必须包含统一的错误处理逻辑
- 必须区分不同类型的错误（网络错误、权限错误、业务错误）并给出相应提示
- 请求超时必须有合理的处理机制

### 7.3 异常处理规范
- 所有可能抛出异常的操作必须使用 try-catch
- catch 块必须处理错误，不允许空 catch
- 异常信息必须记录日志，便于排查问题

## 测试规范

### 8.1 开发测试要求（强制执行）
- **每一步开发完成后必须立即测试，不得跳过或延迟**
- 开发流程：开发功能 → 立即测试功能 → 修复问题 → 继续下一个功能
- 不能等到所有功能开发完成后再测试
- 功能开发完成后必须进行完整的功能测试
- 性能优化后必须验证性能指标是否达标
- **测试是开发的一部分，不是额外的步骤**

### 8.2 测试内容要求
- **功能测试**：
  - 测试所有用户交互流程
  - 测试正常场景和异常场景
  - 测试边界条件（空数据、超长文本、极端值等）
  
- **性能测试**：
  - 测试页面加载时间
  - 测试列表滚动流畅度
  - 测试网络请求响应时间
  
- **兼容性测试**：
  - 测试不同微信版本兼容性
  - 测试不同设备屏幕适配
  - 测试不同操作系统版本

### 8.3 测试环境规范
- 必须测试不同网络环境（WiFi、4G、弱网）
- 必须在多个真实设备上验证兼容性

### 8.4 测试文档要求
- 重要功能必须记录测试用例
- 发现的问题必须记录并修复
- 修复后必须进行回归测试

## 📌 强制执行规则

### ✅ 必须遵守的规则
1. **所有用户输入必须经过 `msgSecCheck` 安全检测**
2. **匿名化处理用户数据，不存储真实身份信息**
3. **所有异步操作必须有加载状态和错误处理**
4. **性能敏感操作必须优化（列表渲染、频繁更新）**
5. **网络请求必须统一封装，包含错误处理**
6. **每一步开发完成后必须立即测试，不得跳过或延迟**

### ⚠️ 常见陷阱（避免）
1. **不要频繁调用 setData**：合并多次更新为一次
2. **不要忘记处理云函数错误**：所有调用都要 try-catch
3. **不要直接修改 data 对象**：必须使用 setData
4. **不要忽略权限配置**：数据库权限必须配置正确
5. **不要使用过大的图片**：压缩后再上传
6. **不要跳过或延迟测试**：每次开发完成后必须立即测试，不得等待
7. **不要等到所有功能开发完成后再进行测试**：每步开发后立即测试
8. **不要绕过安全检测**：必须通过检测才能发布
